# 商户生产落地清单

> 当前状态：扫码点餐主链路可用（桌台、多二维码、共享购物车、分开下单、合并订单）。
> 距离商户正式营业，还需补齐以下能力。

## P0：没有就不能开业

### 1. 支付闭环
- [ ] 微信支付：商户号、API v3 证书/密钥、AppID、openid、HTTPS 回调
- [ ] 支付回调验签、金额校验、幂等
- [ ] 退款：微信退款、退款审核、状态同步
- [ ] 线下/现金收款：后台“确认收款”
- [ ] 支付失败处理：未支付订单继续支付/取消

### 2. 后厨出餐
- [ ] 堂食订单状态机：待接单 → 制作中 → 已上菜 → 已完成
- [ ] 云打印机/KDS：自动出小票、加菜单、补打
- [ ] 接单/拒单、超时提醒
- [ ] 取餐号/桌号叫号
- [ ] 清台：支付完成后关闭会话、桌台置空闲

### 3. 菜单与商品
- [ ] 库存扣减并发修复（当前锁失败会静默跳过）
- [ ] 售罄实时同步
- [ ] 多门店商品上下架、时段菜单
- [ ] SKU/规格一致性校验
- [ ] 图片 OSS/COS + CDN

### 4. 登录与会员
- [ ] 微信登录（小程序/公众号真实 AppID+Secret）
- [ ] 手机号登录（生产短信服务商）
- [ ] 余额/积分并发扣减修复与对账
- [ ] 优惠券限领、时间、库存、并发超发修复

### 5. 安全与合规
- [ ] HTTPS + ICP 备案 + 小程序 request 域名
- [ ] 关闭 mock 登录、开启验证码
- [ ] Swagger/Actuator/Druid 限制访问
- [ ] 密钥改环境变量/配置中心
- [ ] `/app-api/infra/file/upload` 增加鉴权
- [ ] 共享会话 sessionId 改为随机 key + 参与者校验
- [ ] 限流/幂等启用

### 6. 运维与稳定性
- [ ] MySQL/文件每日备份与恢复演练
- [ ] 监控告警（JVM、端口、慢 SQL、支付失败率）
- [ ] 日志按天滚动、操作审计
- [ ] 多实例：WebSocket 改 Redis 发送器
- [ ] 高峰并发压测
- [ ] CI/CD 与回滚

## 已知代码风险

1. 订单状态为外卖语义，堂食需独立状态机
2. 库存校验/扣减锁不一致，失败静默跳过
3. 优惠券领取未校验限领/时间/库存
4. 积分兑换未乘数量，可能负积分
5. `/app-api/**` 整体放行
6. accessToken 为 UUID（Redis+MySQL），非 JWT
7. `.env.prod` 的 `VITE_BASE_URL` 仍为 localhost
8. Dockerfile 使用 JDK21 且端口不一致
9. 多租户/Lock4j/BizTrace 未启用
10. 明文密钥与本地地址残留

## 建议上线路径

### 第一阶段（1–2 周）：能收钱、能出餐
1. 微信支付或线下收款
2. 堂食状态机 + 接单/完成
3. 云打印机小票
4. 生产配置 + HTTPS + 小程序提审

### 第二阶段（1–2 周）：稳定运营
1. 清台/桌台状态
2. 退款/取消
3. 订阅消息
4. 备份监控
5. 并发压测与修复

### 第三阶段：精细化经营
1. 报表对账
2. 员工权限
3. 营销/储值
